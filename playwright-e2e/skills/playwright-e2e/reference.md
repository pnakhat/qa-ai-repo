# Playwright E2E — Setup & Reference

Config patterns, fixture wiring, auth state, and useful commands.
Check the installed version's docs for API drift; the shapes below are stable.

## Install

```bash
npm init playwright@latest          # new project: scaffolds config + example
npm i -D @playwright/test           # existing project
npx playwright install              # download browser binaries
npx playwright install --with-deps chromium  # CI: only the browsers you run, + OS deps
```

## Project layout

```
tests/
  e2e/              # spec files — named by user journey
    checkout-guest.spec.ts
    login.spec.ts
  pages/            # Page Objects — one class per page / major component
    LoginPage.ts
    CheckoutPage.ts
  fixtures/         # Playwright fixture extensions (auth, seeded data, etc.)
    index.ts
    storageState/
      customer.json  # generated by global setup; gitignored
      admin.json
playwright.config.ts
global.setup.ts     # the 'setup' project: logs in once, writes storage states
```

## Config — `playwright.config.ts`

```ts
import { defineConfig, devices } from '@playwright/test';

export default defineConfig({
  testDir: './tests/e2e',
  fullyParallel: true,
  forbidOnly: !!process.env.CI,       // a committed test.only fails CI
  retries: process.env.CI ? 1 : 0,   // detect flakes on CI (reported as "flaky"), never to hide them
  // failOnFlakyTests: !!process.env.TRUNK,  // ≥1.52 — make flaky results fail the trunk/nightly run
  workers: process.env.CI ? 4 : undefined,
  reporter: process.env.CI
    ? [['github'], ['html', { open: 'never' }], ['junit', { outputFile: 'test-results/junit.xml' }]]
    : [['html']],
  // Starts the app under test; skipped when BASE_URL points at a deployed env.
  webServer: process.env.BASE_URL ? undefined : {
    command: 'npm run dev',
    url: 'http://localhost:3000',
    reuseExistingServer: !process.env.CI,
  },
  use: {
    baseURL: process.env.BASE_URL ?? 'http://localhost:3000',
    trace: 'on-first-retry',          // needs retries > 0; use 'retain-on-failure' if retries are 0
    screenshot: 'only-on-failure',
    video: 'retain-on-failure',
  },
  projects: [
    // Setup project creates auth storage states — runs before test projects that
    // list it in `dependencies` (preferred over the `globalSetup` option: it shows
    // in the report, records traces, and can use fixtures).
    // testDir: '.' is required: the top-level testDir above scopes discovery to
    // ./tests/e2e, so a root-level global.setup.ts is never found, the setup
    // project matches zero tests, and every test fails with ENOENT on the
    // storageState file below.
    { name: 'setup', testDir: '.', testMatch: /global\.setup\.ts/ },
    {
      name: 'chromium',
      use: {
        ...devices['Desktop Chrome'],
        storageState: 'tests/fixtures/storageState/customer.json',
      },
      dependencies: ['setup'],
    },
  ],
});
```

## Global setup — create auth storage state once

`global.setup.ts`:

```ts
import { test as setup, expect } from '@playwright/test';
import path from 'path';

const CUSTOMER_STATE = path.join('tests/fixtures/storageState', 'customer.json');

setup('authenticate as customer', async ({ page }) => {
  await page.goto('/login');
  await page.getByLabel('Email').fill(process.env.TEST_USER_EMAIL!);
  await page.getByLabel('Password').fill(process.env.TEST_USER_PASSWORD!);
  await page.getByRole('button', { name: 'Sign in' }).click();
  await expect(page).toHaveURL('/dashboard');
  await page.context().storageState({ path: CUSTOMER_STATE });
});
```

Add `tests/fixtures/storageState/*.json` to `.gitignore` — they contain session tokens
that can impersonate the test account. (Playwright's docs use `playwright/.auth/`;
any gitignored path works.) If tokens expire within a run, re-authenticate in the
setup project rather than adding retries.

**Accounts that tests mutate.** One shared storage state is fine for read-mostly
journeys. If tests change the account's server-side state in parallel, give each
worker its own account with a worker-scoped fixture:

```ts
export const test = base.extend<{}, { workerStorageState: string }>({
  storageState: ({ workerStorageState }, use) => use(workerStorageState),
  workerStorageState: [async ({ browser }, use) => {
    const id = test.info().parallelIndex;            // stable per worker
    const file = `tests/fixtures/storageState/worker-${id}.json`;
    const page = await browser.newPage({ storageState: undefined });
    // log in as acct-${id} (pre-provisioned or created via API), then:
    await page.context().storageState({ path: file });
    await page.close();
    await use(file);
  }, { scope: 'worker' }],
});
```

Because `storageState` is set at the **project** level, a test that must start logged out
overrides it per-file rather than deleting the default:

```ts
test.use({ storageState: { cookies: [], origins: [] } });
```

## Fixtures — extend `@playwright/test`

`tests/fixtures/index.ts`:

```ts
import { test as base } from '@playwright/test';
import { LoginPage } from '../pages/LoginPage';
import { CheckoutPage } from '../pages/CheckoutPage';

type AppFixtures = {
  loginPage: LoginPage;
  checkout: CheckoutPage;
};

export const test = base.extend<AppFixtures>({
  loginPage: async ({ page }, use) => {
    await use(new LoginPage(page));
  },
  checkout: async ({ page }, use) => {
    await use(new CheckoutPage(page));
  },
});

export { expect } from '@playwright/test';
```

Import `test` from `../fixtures` (not from `@playwright/test`) in all spec files.

## Page Object pattern

```ts
// tests/pages/CheckoutPage.ts
import { Page, Locator } from '@playwright/test';

export class CheckoutPage {
  readonly page: Page;
  readonly orderConfirmation: Locator;

  constructor(page: Page) {
    this.page = page;
    this.orderConfirmation = page.getByRole('heading', { name: 'Order confirmed' });
  }

  async addToCart(sku: string) {
    await this.page.getByTestId(`add-to-cart-${sku}`).click();
  }

  async placeOrder(): Promise<void> {
    await this.page.getByRole('button', { name: 'Place order' }).click();
    // Returns void; caller asserts the outcome in the spec
  }
}
```

- Locators are defined as class properties (lazy, always fresh — no stale element handles).
- Methods return `void` or the next Page Object; they do **not** contain `expect()` calls.

## Spec pattern

```ts
// tests/e2e/checkout-guest.spec.ts
import { test, expect } from '../fixtures';

test.describe('Guest checkout', () => {
  test('places an order and receives confirmation', async ({ checkout, page }) => {
    await page.goto('/products');
    await checkout.addToCart('SKU-001');
    await page.getByRole('link', { name: 'Cart' }).click();
    await checkout.placeOrder();
    await expect(checkout.orderConfirmation).toBeVisible();
    await expect(page).toHaveURL(/\/orders\/\d+/);
  });
});
```

## Test data — create, track, tear down

Seed preconditions through the API (`request` fixture), not the UI. The fixture
creates the data, hands it to the test, and deletes it afterwards — the code after
`use()` runs whether the test passed or failed.

`tests/fixtures/data.ts`:

```ts
import { test as base, expect } from '@playwright/test';
import { randomUUID } from 'node:crypto';

// One id per run (set TEST_RUN_ID in CI so the sweeper can find a crashed run's data).
const RUN_ID = process.env.TEST_RUN_ID ?? randomUUID().slice(0, 8);

// Destructive setup/teardown only against allowlisted hosts — never prod or shared envs.
const SAFE_HOSTS = (process.env.E2E_SAFE_HOSTS ?? 'localhost,127.0.0.1').split(',');
function assertSafeTarget(baseURL: string | undefined) {
  const host = new URL(baseURL ?? 'http://localhost').hostname;
  if (!SAFE_HOSTS.includes(host)) throw new Error(`Refusing to seed or delete data on ${host}`);
}

type Customer = { id: string; email: string };
type DataFixtures = {
  uid: string;                                // unique per test + worker + run
  track: (resourceUrl: string) => void;       // register anything the test creates
  customer: Customer;
};

export const test = base.extend<DataFixtures>({
  uid: async ({}, use, testInfo) => {
    await use(`e2e-${RUN_ID}-w${testInfo.workerIndex}-${randomUUID().slice(0, 6)}`);
  },

  // Deletes every tracked resource, newest first, even when the test failed.
  track: async ({ request, baseURL }, use) => {
    assertSafeTarget(baseURL);
    const created: string[] = [];
    await use((url) => { created.push(url); });
    for (const url of created.reverse()) {
      const res = await request.delete(url);
      expect([200, 204, 404]).toContain(res.status());   // 404: the test already deleted it
    }
  },

  customer: async ({ request, uid, track }, use) => {
    const res = await request.post('/api/customers', {
      data: { email: `${uid}@example.test`, name: uid },
    });
    expect(res.ok()).toBeTruthy();
    const customer: Customer = await res.json();
    track(`/api/customers/${customer.id}`);
    await use(customer);
  },
});

export { expect } from '@playwright/test';
```

Merge it into `tests/fixtures/index.ts` (`mergeTests(pageFixtures, dataFixtures)`)
so specs keep importing one `test`.

```ts
test('displays a previously placed order', async ({ page, request, customer, track }) => {
  const res = await request.post('/api/orders', {
    data: { customerId: customer.id, items: [{ sku: 'SKU-001', qty: 1 }] },
  });
  const { id } = await res.json();
  track(`/api/orders/${id}`);                     // deleted before the customer

  await page.goto(`/orders/${id}`);
  await expect(page.getByText('SKU-001')).toBeVisible();
});
```

Notes:
- Data that a whole worker shares (a per-worker account) goes in a
  `{ scope: 'worker' }` fixture with the same create → `use` → delete shape; tests
  may read it but must not mutate it.
- **Sweeper** for orphans from crashed or cancelled runs — a scheduled CI job, scoped
  by prefix and age, never by "everything":
  ```sql
  DELETE FROM customers WHERE email LIKE 'e2e-%' AND created_at < now() - interval '6 hours';
  ```
- **No-cleanup isolation** where the app supports it: create one tenant/org per run
  in a setup project and delete the tenant in its teardown project
  (`teardown: 'cleanup db'` in the setup project's config).
- **Check the hygiene**:
  ```bash
  npx playwright test --repeat-each=2                  # second run must not trip on the first
  npx playwright test --fully-parallel --workers=4     # no collisions between workers
  npx playwright test -g "displays a previously placed order"   # passes alone
  ```
  Then query for the run's prefix (`e2e-$TEST_RUN_ID-`): zero rows left.

## Locator chaining & filtering

```ts
// Scope to a container, then pick by accessible name — no indexes, no CSS.
const row = page.getByRole('row').filter({ hasText: 'INV-1042' });
await row.getByRole('button', { name: 'Refund' }).click();
await expect(row.getByRole('cell', { name: 'Refunded' })).toBeVisible();

// Lists: assert count/content, retrying until the UI settles.
await expect(page.getByRole('listitem')).toHaveCount(3);
await expect(page.getByRole('listitem')).toHaveText(['Apples', 'Bananas', 'Cherries']);

// Several independent checks on one screen — report all failures, not just the first.
await expect.soft(page.getByTestId('subtotal')).toHaveText('$90.00');
await expect.soft(page.getByTestId('tax')).toHaveText('$7.20');
```

Use `npx playwright codegen` or the VS Code extension's "Pick locator" to get a
first candidate, then tighten it by hand.

## Network interception

```ts
// Stub a slow or third-party endpoint
await page.route('**/api/recommendations', async route => {
  await route.fulfill({ json: { items: [] } });
});

// Assert a request was made
const responsePromise = page.waitForResponse(
  resp => resp.url().includes('/api/orders') && resp.status() === 201,
);
await checkout.placeOrder();
await responsePromise; // fails fast if the request never happens
```

Routes registered on `page` or the test's `context` are discarded with that context
at the end of the test; register them **before** the action that triggers the request.

## Useful commands

```bash
npx playwright test                        # run all tests (headless)
npx playwright test checkout               # run tests matching 'checkout'
npx playwright test --project=chromium     # one browser
npx playwright test --headed               # watch it run
npx playwright test --ui                   # time-travel UI runner
npx playwright test --trace on             # always record traces
npx playwright show-trace trace.zip        # inspect a saved trace
npx playwright test --debug                # headed + Inspector, paused at the first action
npx playwright codegen http://localhost:3000  # record a test interactively
npx playwright test --grep @smoke          # run tagged subset (tag: test('…', { tag: '@smoke' }, …))
npx playwright test --repeat-each=10 --workers=4 checkout  # shake out a suspected flake
npx playwright test --last-failed          # re-run only what failed last time
npx playwright test --only-changed=origin/main  # specs affected by changes vs a ref
npx playwright test --shard=1/4 --reporter=blob  # one CI shard
npx playwright merge-reports --reporter=html ./all-blob-reports  # combine shards
```

## Live-browser exploration with the Playwright MCP server

Installing this objective wires the `@playwright/mcp` server into `.mcp.json`
(Claude Code) or `.cursor/mcp.json` (Cursor), pinned to a stable release
(`@playwright/mcp@0.0.83`, not `@latest`) so tool names don't change under the
agents; bump the pin deliberately. Use it to:

- Navigate the live app and discover stable locators before writing specs.
- Verify that a user journey completes end-to-end interactively.
- Debug a failing spec by re-running the steps manually with MCP browser control.

The MCP server drives a real browser; it does not replace `npx playwright test` for
automated runs but is invaluable for exploration, locator discovery, and live debugging.
Useful args (append to `args` in the MCP config): `--isolated` (in-memory profile, no
leaked state between sessions), `--storage-state=<file>` (start logged in), `--headless`,
`--browser=firefox|webkit|msedge`. Never point it at production with a privileged account.

## Playwright test agents — plan → generate → heal

Playwright ≥ 1.56 ships planner, generator, and healer agent definitions that use
the `playwright-test` MCP server (`npx playwright run-test-mcp-server`, also
installed by this objective).

```bash
cp .mcp.json .mcp.json.bak                 # init-agents overwrites .mcp.json
npx playwright init-agents --loop=claude   # writes .claude/agents/playwright-test-*.md + .mcp.json
npx qa-ai-repo add playwright-e2e          # idempotent: restores the "playwright" server it dropped
npx playwright init-agents --loop=vscode   # or codex / opencode; re-run after upgrading Playwright
```

`init-agents` replaces the loop's MCP config with only `playwright-test`. Merge
back anything else it dropped from the backup. Plugin installs get their servers
from the plugin, so they are unaffected.

- **Seed** (`tests/seed.spec.ts`): the test every generated test starts from. Import
  the project's fixtures in it so auth state and page objects carry through.
- **Planner** → `specs/<name>.md`. **Generator** → one spec per plan scenario.
  **Healer** → fixes failing specs, or marks them `test.fixme()` if the app is broken.
- Generated code uses raw `page.*` calls; refactor it into Page Objects before merging.

## CI gate example (GitHub Actions)

```yaml
- uses: actions/setup-node@v4
  with: { node-version: lts/*, cache: npm }
- run: npm ci
- run: npx playwright install --with-deps chromium

- name: Run Playwright tests
  run: npx playwright test
  env:
    BASE_URL: ${{ vars.STAGING_URL }}
    TEST_USER_EMAIL: ${{ secrets.TEST_USER_EMAIL }}
    TEST_USER_PASSWORD: ${{ secrets.TEST_USER_PASSWORD }}

- name: Upload test artifacts
  if: ${{ !cancelled() }}       # also on pass, so flaky-test traces are kept
  uses: actions/upload-artifact@v4
  with:
    name: playwright-report
    path: |
      playwright-report/
      test-results/
    retention-days: 14
```

For large suites, run a `strategy.matrix` of shards (`--shard=${{ matrix.shard }}/4`
with `--reporter=blob`), upload each `blob-report/`, then a final job downloads them
and runs `npx playwright merge-reports --reporter=html ./all-blob-reports`.
