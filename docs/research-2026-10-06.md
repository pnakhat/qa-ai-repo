# Quality engineering research and decisions

Reviewed 2026-10-06. This is a selection of primary documentation and internationally maintained open-source projects, not an exhaustive global survey. Recommendations were compared with the repository's actual failure modes. No third-party skill code was vendored.

| Source | Adopted decision | Boundary |
|---|---|---|
| [Anthropic skill-creator](https://github.com/anthropics/skills/tree/main/skills/skill-creator) | Observable failure probes and separate reference material | Structural validation does not establish model effectiveness; comparative agent evals need separate runs |
| [Anthropic webapp-testing](https://github.com/anthropics/skills/tree/main/skills/webapp-testing) | Inspect the rendered app and manage server lifecycle | Rejected its generic networkidle/sleep advice in favor of application readiness |
| [Microsoft Playwright CLI skills](https://github.com/microsoft/playwright-cli/tree/main/skills/playwright-cli) | Pick direct runner/CLI for focused tasks; MCP for stateful exploration | Do not introduce another browser stack into an already working project |
| [Microsoft Playwright agents](https://playwright.dev/docs/test-agents) | Explore, generate, verify; use installed-version definitions | Healing is bounded and cannot replace assertions with skips |
| [Playwright MCP](https://github.com/microsoft/playwright-mcp) | Isolated browser profile, pinned package, actual navigation probe | Isolation separates profile state; it is not a security sandbox or a network authorization boundary |
| [MCP lifecycle](https://modelcontextprotocol.io/specification/2025-06-18/basic/lifecycle) | Await initialization, then notification, discovery, and calls | A successful handshake only establishes connection and advertised capabilities |
| [Playwright Page API](https://playwright.dev/docs/api/class-page#page-wait-for-load-state) | Use web assertions for readiness and pre-register response waiters | Polling/streaming apps make networkidle a poor readiness signal |
| [Cucumber example mapping](https://cucumber.io/docs/bdd/example-mapping/) | Business rules, examples, questions; migration scenario parity | Gherkin syntax alone is not collaborative BDD |
| [Pact pending pacts](https://docs.pact.io/pact_broker/advanced_topics/pending_pacts) | Distinguish pending failure from positive compatibility | A non-blocking provider build does not prove safe deployment |
| [Schemathesis stateful testing](https://schemathesis.readthedocs.io/en/stable/explanations/stateful/) | Test sequences and preserve minimal reproductions | Schema checks do not establish business correctness or authorization |
| [fast-check model testing](https://fast-check.dev/docs/advanced/model-based-testing/) | State-machine invariants, shrinking, seed/replay evidence | Use where input/state space warrants it, not as mandatory infrastructure |
| [Stryker mutant metrics](https://stryker-mutator.io/docs/mutation-testing-elements/mutant-states-and-metrics/) | Report mutant states and denominators; kill concrete faults | Invalid/equivalent mutants and errors need separate interpretation |
| [Grafana k6 thresholds](https://grafana.com/docs/k6/latest/using-k6/thresholds/) | Make latency, errors, and checks executable gates | A recorded check does not fail the process without a threshold |
| [Grafana k6 redirects](https://grafana.com/docs/k6/latest/using-k6/k6-options/reference/) | Disable automatic redirects in guarded examples and reject ambiguous URL authorities | Host checks are not DNS/network isolation |
| [Grafana k6 built-in metrics](https://grafana.com/docs/k6/latest/using-k6/metrics/reference/) | Report delivered load and dropped iterations | Under-delivered load invalidates target-capacity claims |
| [Playwright accessibility](https://playwright.dev/docs/accessibility-testing) | Combine scans with interaction and manual review | Clean axe output is not conformance certification |
| [Playwright screenshots](https://playwright.dev/docs/test-snapshots) | Match rendering environment; challenge baseline with visible defect | Missing or updated baselines are not successful comparisons |
| [Promptfoo assertions](https://www.promptfoo.dev/docs/configuration/expected-outputs/) | Deterministic gates before semantic judges, retain failure reasons | Harness tests do not measure provider/model quality |

## Review lenses

- Developer: preserve local configuration, portable resource paths, binary integrity, bounded child processes, repeatable installation, and no silent package downloads for the project runner.
- SDET: prove checks fail for seeded faults, inspect test discovery and skipped counts, parallel/repeat isolation, error-path cleanup, and distinguish runtime evidence from static checks.
- QA leader: map customer risk to evidence and a release decision; record owner, exceptions, missing checks, environment limitations, and testing cost.

Each of the 12 shipped skills includes a `verification.md` decision guide with five domain-specific scenario classes. The guides travel with each independent objective and its installed rules. They extend coverage without forcing unrelated tools or new dependencies into consumer projects.
